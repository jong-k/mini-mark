# 찾기 기능 구현 계획

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Goal: Cmd+F로 여는 찾기 바를 붙여 현재 문서 안의 일치를 표시하고 이동한다. 바꾸기는 범위 밖이다.

Architecture: 매칭과 일치 표시, 스크롤, 닫을 때 선택은 `src/markdown-editor.ts`의 ProseMirror 플러그인이 맡고, 상위 컴포넌트는 `EditorHandle.find` 핸들로만 접근한다. 찾기 바는 `src/find-bar.tsx`의 React 컴포넌트이고 `Editor`가 본문 옆에 렌더한다. `App`은 찾기를 모른다. Cmd+F, Cmd+G, Cmd+Shift+G는 Edit 메뉴 accelerator가 받아 Rust가 `find-action` 이벤트로 보낸다. 찾기는 문서를 바꾸는 트랜잭션을 만들지 않는다.

Tech Stack: @milkdown/kit(ProseMirror `Decoration.inline`, `$ctx`, `$prose`), React 19, lucide-react 1.59.0, Tauri v2 메뉴, Vitest + jsdom

Spec: `docs/spec/find.md`

## Global Constraints

- 의존성 추가는 `lucide-react` 하나다. `pnpm add -E lucide-react@1.59.0`으로 고정한다(1.60.0은 2026-10-20 배포라 하루가 안 됐다).
- `App`은 React 상태를 갖지 않고 찾기를 모른다. 본문 접근은 `EditorHandle.find`로만 한다. 컴포넌트가 ProseMirror를 직접 만지지 않는다.
- 찾기는 문서를 바꾸지 않는다. 플러그인은 `setMeta` 트랜잭션만 보내고, `docChanged` 플러그인의 `onChange`가 울리지 않아야 한다. `isDirty`와 undo 기록에 영향이 없다.
- 단축키는 메뉴 accelerator 경로만 쓴다. 웹뷰 `keydown`으로 Cmd+F, Cmd+G, Cmd+Shift+G를 받지 않는다(둘 다 받으면 두 번 실행된다. `menu.rs` 주석).
- 입력란 안의 키(Enter, Shift+Enter, 위아래 화살표)는 입력란 `onKeyDown`이, Esc는 `window` `keydown` 리스너가 받는다.
- 매칭은 대소문자를 무시한 리터럴이다. 검색어를 정규식 이스케이프한 뒤 `gi` 플래그로 찾는다. 디바운스는 100ms다.
- 화면 문구: 자리 표시 "찾기", 개수 `현재 / 전체`(예: `3 / 12`), 일치 없음 "결과 없음". `aria-label`: 입력란 "찾기", 지우기 "찾기 닫기", 위 화살표 "이전 일치", 아래 화살표 "다음 일치". 개수 영역은 `aria-live="polite"`.
- 색은 `src/app.css`의 기존 변수(`--bg`, `--fg`, `--muted`, `--border`, `--code-bg`, `--accent`)만 쓴다.
- 가운뎃점 문자를 쓰지 않는다. 커밋 메시지는 `docs/conventions/commit-convention.md`를 따르고 본문 없이 Co-Authored-By 꼬리말만 붙인다.
- 커밋 전 `pnpm lint`, `pnpm fmt:check`, `pnpm test`를 통과시킨다. Rust를 바꾼 커밋은 `pnpm fmt:rs`, `pnpm lint:rs`도 통과시킨다.

## Review Focus

- 이미지나 하드 브레이크가 섞인 문단에서 일치 위치가 한 칸씩 밀리면 안 된다. 인라인 리프 노드는 한 자리를 차지한다(Task 1 테스트).
- 검색어에 `.`, `(`, `*` 같은 정규식 문자가 있어도 글자 그대로 찾아야 한다(Task 1 테스트).
- 편집으로 일치가 0개가 되거나 현재 일치가 지워져도 `current`가 범위 밖을 가리키지 않아야 한다(Task 2 테스트).
- 디바운스가 대기 중일 때 Enter를 누르면 검색만 하고 이동하지 않아야 한다. 한글 조합 확정 Enter가 한 칸 건너뛰면 안 되고, 입력 직후 시작한 조합 중에 예약된 검색이 돌면 안 된다(Task 4 테스트).
- 바가 열린 채 다른 문서를 열어도(`setValue`) 검색어가 남고 개수가 새 문서 기준이어야 한다. `replaceAll`이 `EditorState`를 새로 만들어 플러그인 `init`이 다시 돌기 때문에 검색어는 `$ctx`에 둔다(Task 2 테스트).

```ts
// src/editor.tsx
export interface FindState {
  query: string;
  count: number;
  /** 0부터 센다. 일치가 없으면 -1. */
  current: number;
}
export interface FindHandle {
  /** 검색어를 바꾸고 커서 이후 첫 일치를 현재로 삼는다. 빈 문자열이면 표시를 지운다. */
  search(query: string): void;
  step(delta: 1 | -1): void;
  /** 표시를 지우고, 현재 일치가 있으면 그 범위를 선택한 채 본문에 포커스를 준다. */
  close(): void;
  /** 본문 선택 텍스트. 없거나 줄바꿈이 있으면 빈 문자열. */
  selectionText(): string;
  /** 상태가 바뀔 때마다 부른다. 해제 함수를 돌려준다. */
  onChange(listener: (state: FindState) => void): () => void;
}
export interface EditorHandle {
  getValue(): string;
  setValue(value: string): void;
  setFilePath(path: string | null): void;
  find: FindHandle;
}
```

- [ ] Step 4: `src/markdown-editor.ts`에 플러그인과 핸들 구현

- `findRequest = $ctx<{ query: string }, "findRequest">({ query: "" }, "findRequest")`. 핸들의 `search`와 `close`가 갱신하고 플러그인 `init`이 읽는다. `setValue`의 `replaceAll(flush=true)`가 상태를 새로 만들어도 검색이 이어지게 하기 위해서다.
- `findListeners = $ctx<Set<(s: FindState) => void>, "findListeners">`. 기본값 Set이 에디터 인스턴스 사이에 공유되지 않도록 `createMarkdownEditor`의 `config`에서 `ctx.set(findListeners.key, new Set())`으로 새로 만든다.
- `FIND_KEY = new PluginKey<FindPluginState>("find")`, 상태는 `{ query, matches, current, decorations: DecorationSet, scroll: boolean }`. `build(query, doc, pos, scroll)` 헬퍼가 Task 1 함수로 상태를 만든다. 표시는 `Decoration.inline(from, to, { class })`이고 클래스는 `find-match`, 현재 일치만 `find-match find-match-current`다.
- 데코레이션은 `decorate(doc, matches, current)` 헬퍼가 만들고 `build`와 `step`이 모두 이 헬퍼를 쓴다. 현재 일치 클래스가 `DecorationSet` 안에 있으므로 `current`만 바꾸면 표시와 스크롤 대상이 옛 일치에 남는다.
- `apply`: 메타 `{ type: "search", query }`는 `build(query, doc, selection.from, true)`, `{ type: "step", delta }`는 `wrapIndex`로 `current`를 바꾸고 `decorate`로 데코레이션을 다시 만들며 `scroll: true`, `{ type: "close" }`는 빈 상태. 메타가 없고 `tr.docChanged`면 이전 검색어로 다시 `build`하되 `pos`는 이전 현재 일치의 `from`을 `tr.mapping.map`한 값, `scroll: false`. 그 외는 이전 상태 그대로.
- 플러그인 `view` 팩토리는 만들어질 때 `findListeners`에 현재 `FindState`를 한 번 보낸다. `setValue`의 `replaceAll`은 `plugins: ctx.get(prosePluginsCtx)`로 새 상태를 만들어 `prev.plugins != state.plugins`가 되고, ProseMirror가 플러그인 view를 모두 버리고 다시 만들어 기존 `update`는 불리지 않기 때문이다.
- `view.update(view, prevState)`: 플러그인 상태 객체가 바뀌었을 때만 동작한다. `scroll`이 참이고 `current >= 0`이면 `view.dom.querySelector(".find-match-current")?.scrollIntoView?.({ block: "center" })`를 부른다(jsdom에는 `scrollIntoView`가 없어 옵셔널 호출). `query`, `count`, `current` 중 하나라도 바뀌면 `findListeners`에 `FindState`를 보낸다.
- `editorHandle(editor)`의 `find`: `search`는 `findRequest`를 갱신하고 메타를 dispatch, `step`은 메타만, `close`는 `findRequest`를 비우고 현재 일치가 있으면 `tr.setMeta(FIND_KEY, { type: "close" }).setSelection(TextSelection.create(doc, from, to)).scrollIntoView()`를 한 트랜잭션으로 보낸 뒤 `view.focus()`. `selectionText`는 `doc.textBetween(from, to, "\n")`에 줄바꿈이 있으면 빈 문자열. `onChange`는 `findListeners`에 넣고 해제 함수를 돌려준다.
- `.use(findPlugin)`, `.use(findRequest)`, `.use(findListeners)`를 `create()` 앞에 더한다.

- [ ] Step 4: `src/find-bar.tsx` 구현

- 상태: `open`, `query`, `state: FindState`. ref: 입력란, 디바운스 타이머, `composing`, `searched`(마지막으로 `find.search`에 보낸 검색어), 그리고 이벤트 핸들러가 최신값을 읽도록 `open`과 `query`의 ref(`app.tsx`의 `doc` ref와 같은 이유).
- `runSearch(q)`: 타이머 취소, `searched = q`, `find.search(q)`. `schedule(q)`: 타이머를 100ms로 다시 건다. `onChange`는 `setQuery` 뒤 조합 중이 아니면 `schedule`. `onCompositionStart`는 대기 중인 타이머를 취소하고 `composing = true`(입력 뒤 100ms 안에 조합을 시작하면 예약된 검색이 조합 중에 돌기 때문), `onCompositionEnd`는 `composing = false` 뒤 `schedule`.
- `onKeyDown`: `event.nativeEvent.isComposing`이면 무시(React의 `KeyboardEvent` 타입에는 `isComposing`이 없다). Enter, Shift+Enter, ArrowDown, ArrowUp은 `preventDefault` 뒤 `query !== searched`면 `runSearch(query)`만, 같으면 `find.step(±1)`.
- `openBar(prefill: boolean)`: 이미 열려 있으면 입력란 `focus()`와 `select()`만. 아니면 `prefill`이 참이고 `find.selectionText()`가 비어 있지 않으면 그 값을 `query`로 삼고, `setOpen(true)`, 검색어가 있으면 `runSearch`. 선택 텍스트 가져오기는 Cmd+F 경로에만 있다. 포커스와 전체 선택은 `open`을 의존성으로 둔 `useEffect`에서 한다.
- `close()`: 타이머 취소, `setOpen(false)`, `find.close()`. 지우기 버튼은 `setQuery("")` 뒤 `close()`.
- 마운트 effect: `onFindAction`을 구독해 `find`는 `openBar(true)`, `findNext`와 `findPrev`는 닫혀 있으면 `openBar(false)` 뒤 검색어가 있으면 `find.step(±1)`, 열려 있으면 `find.step(±1)`. `find.onChange(setState)`도 구독한다. 둘 다 해제 함수를 cleanup에서 부른다.
- `open`일 때만 `window`에 `keydown` 리스너를 걸어 `Escape`면 `close()`.
- 렌더: `.find-bar` 안에 `.find-field`(`Search` 아이콘, 입력란, `.find-count`, `X` 버튼)와 `.find-arrows`(`ChevronUp`, `ChevronDown` 버튼). 아이콘은 `size={16}`, `strokeWidth={2}`, `aria-hidden`. 화살표 버튼은 `onMouseDown`에서 `preventDefault`해 입력란 포커스를 유지한다. 개수 글자는 `state.query === ""`면 빈 문자열, `state.count`가 0이면 "결과 없음"(`find-count empty`), 아니면 `${state.current + 1} / ${state.count}`.
