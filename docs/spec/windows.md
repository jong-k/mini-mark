# 창 스펙

여러 창을 열고 문서를 어느 창에서 열지 정한다. 구현은 `src-tauri/src/windows.rs`(라우팅, 창 생성, 종료)와 `src/app.tsx`(창별 문서 상태 보고)에 두고, 자동 테스트는 `windows.rs`의 순수 함수 테스트에 둔다.

- 작성일: 2026-11-02
- 상태: 구현 완료. 디버그 번들로 Finder 열기 경로 검증 완료(2026-11-02). 메뉴와 키보드 항목은 손쉬운 사용 권한이 없어 자동 검증하지 못했다. 아래 "확인 필요" 참고
- 범위: 창 생성과 열기 라우팅, 종료. 탭, 창 위치 기억, 세션 복원은 범위 밖이다.

## 배경

창이 하나라 다른 문서를 열면 현재 문서를 버려야 하고, Finder에서 여러 파일을 열면 첫 파일만 열린다. Typora 1.14.10과 VS Code의 동작을 참고했다.

| 항목             | Typora                         | VS Code                              | mini-mark |
| ---------------- | ------------------------------ | ------------------------------------ | --------- |
| Cmd+N            | 빈 문서로 새 창                | 현재 창에 새 탭, Cmd+Shift+N이 새 창 | Typora    |
| 파일 열기        | 빈 창이면 거기서, 아니면 새 창 | 현재 창에 새 탭                      | Typora    |
| 같은 파일 재열기 | 이미 연 창을 앞으로            | 이미 연 탭으로                       | Typora    |
| 마지막 창 닫기   | 앱 유지                        | 앱 유지                              | 앱 유지   |
| 창 개수          | 제한 없음                      | 제한 없음                            | 제한 없음 |

## 동작

### 새 창

- File 메뉴 "New"(Cmd+N)는 항상 빈 문서로 새 창을 연다. 현재 창이 비어 있어도 새 창을 연다. 현재 창의 문서는 건드리지 않는다.
- 새 창의 크기와 제목, 드래그 앤 드롭 설정은 `tauri.conf.json`의 첫 창과 같다. 앞 창(포커스된 창)이 있으면 그 창에서 오른쪽 아래로 24pt 떨어진 위치에 띄운다. 없으면 시스템 기본 위치다. 창은 `tauri.conf.json`대로 숨긴 채 만들고, 시스템이 다크 테마면 페이지가 뜨기 전에 흰 화면이 비치지 않도록 창 배경을 `app.css`의 다크 `--bg` 색으로 깐 뒤 보여 준다. Tauri가 setup 전에 만드는 첫 창도 setup에서 같은 처리를 거친다.
- 창 라벨은 첫 창이 `main`, 이후 `win-1`, `win-2`처럼 번호가 늘기만 한다. 닫힌 창의 번호를 다시 쓰지 않는다.

### 빈 창

- 경로가 없고(`filePath === null`) 수정이 없는(`isDirty === false`) 창이다. 본문을 쓴 뒤 모두 지워도 수정이 남아 빈 창이 아니다.
- 각 창의 JS는 `filePath`나 `isDirty`가 바뀔 때마다 Rust에 보고한다. Rust는 창 라벨별로 마지막 보고를 보관한다.

### 파일 열기

Cmd+O, Open Recent, Finder 열기(더블클릭, Dock 드롭), 콜드 스타트 인자는 모두 Rust의 한 함수로 모이고 다음 순서로 창을 고른다.

1. 그 경로를 이미 연 창이 있으면 그 창을 앞으로 가져온다(최소화돼 있으면 복원한다). 다시 읽지 않는다.
2. 웹뷰가 아직 준비되지 않은 창(콜드 스타트의 `main`, 막 만든 새 창)이 있으면 그 창에 보류한다. 창이 준비되면 가져가 연다. macOS는 설정의 `main` 창이 만들어지기 전에 열기 요청을 보낼 수 있으므로, 어떤 창도 준비된 적이 없으면 목록에 없어도 `main`에 보류한다.
3. 앞 창이 빈 창이면 그 창에서 연다. 앞 창이 아니어도 빈 창이 있으면 그중 하나에서 연다. 보낸 즉시 그 창을 그 경로의 창으로 적어 두어, 같은 요청에 들어온 다음 파일이 같은 창을 다시 쓰지 않는다. 창은 앞으로 가져온다. 열기가 실패하거나 취소되면 창의 JS가 실제 상태를 다시 보고한다.
4. 아니면 새 창을 만들고 그 창에 보류한다.

- Cmd+O는 Rust가 열기 대화상자(Markdown 필터)를 띄운다. 창이 하나도 없어도 동작한다.
- Finder에서 여러 파일을 동시에 열면 파일마다 위 규칙을 적용해 파일마다 창이 생긴다.
- 창 안에서 열린 뒤의 동작(외부 변경 감시, 최근 목록 추가, 수정 중 버리기 확인)은 지금과 같다.

### 메뉴 단축키의 대상

- Save, Save As, Find, Find Next, Find Previous는 앞 창에만 보낸다. 앞 창이 없으면 아무 일도 하지 않는다.
- New, Open, Open Recent, Clear Menu, Quit는 창과 무관하게 동작한다.

### 창 닫기

- Window 메뉴 "Close"(Cmd+W)와 닫기 버튼은 그 창만 닫는다. 수정이 있으면 지금처럼 버리기 확인을 묻는다.
- 마지막 창을 닫아도 앱은 메뉴 바와 함께 남는다. Cmd+N, Cmd+O, Open Recent, Finder 열기로 창을 다시 연다. Dock 아이콘을 눌렀을 때 열린 창이 없으면 빈 창을 열고, 창이 모두 최소화되거나 숨겨져 있으면 그중 하나를 복원한다.

### 종료

- "Quit Mini Mark"(Cmd+Q)는 모든 창을 닫는다. 수정이 있는 창마다 버리기 확인이 뜬다. 하나라도 취소하면 종료를 멈추고 남은 창은 그대로 둔다. 모두 닫히면 앱이 끝난다.
- 창이 하나도 없을 때 Cmd+Q는 바로 끝난다.

### Window 메뉴

- macOS가 열린 창 목록을 Window 메뉴 아래에 자동으로 붙인다. 창 제목은 지금처럼 파일명과 수정 표시(`•`)다.

### 창별 상태

- 문서 상태, 찾기 검색어, 외부 변경 감시, 작업 큐는 창마다 따로다. 최근 목록은 앱 전체가 공유한다.

## 결정과 이유

### 라우팅은 Rust가 한다

열기 요청은 메뉴(Cmd+O), Finder, Open Recent, 콜드 스타트 네 곳에서 오고 셋은 이미 Rust에서 시작한다. 창이 없을 때 Cmd+O도 받아야 하므로 대화상자까지 Rust로 옮기면 열기 경로가 한 함수로 모인다. JS는 자기 창의 상태만 보고한다.

### 보류 경로를 창 라벨별로 둔다

콜드 스타트에서 `main`이 준비되기 전에 온 경로를 보관하던 `OpenedFile`을 라벨별 맵으로 바꾸면, 새 창에 열 파일을 넘기는 데 같은 `take_opened_file` 호출을 그대로 쓴다. URL 쿼리나 초기화 스크립트가 필요 없다.

### 검토했으나 채택하지 않은 대안

| 대안                            | 채택하지 않은 이유                                                       |
| ------------------------------- | ------------------------------------------------------------------------ |
| Cmd+Shift+N을 New Window로 추가 | Cmd+N이 이미 새 창을 열어 같은 동작이 둘이 된다.                         |
| 창 개수 상한                    | Typora, VS Code에 없다. 창당 WKWebView 약 33MB는 사용자가 닫아 조절한다. |
| JS가 빈 창 판단과 새 창 요청    | 창이 없을 때 Cmd+O를 받을 JS가 없다. Rust가 이미 상태를 받으므로 거기서. |

## 알려진 한계

- 창 위치와 크기를 기억하지 않는다. 새 창은 앞 창 기준 오프셋이다.
- 같은 파일을 두 창에서 편집할 수 없다. 두 번째 열기는 첫 창을 앞으로 가져온다.
- Dock 우클릭 종료와 로그아웃은 tao에 훅이 없어 버리기 확인을 타지 않는다(기존과 같다).
- 창이 준비되기 전(웹뷰 로드 중)에 그 창을 닫으면 보류한 경로는 버려진다.
- 콜드 스타트에서 여러 파일을 열면 앞 창이 아직 없어 창들이 같은 위치에 겹친다.

## 확인 필요

디버그 번들(`pnpm tauri build --debug --bundles app`)을 `open -a`로 띄우고 CoreGraphics 창 목록으로 개수와 위치를 세어 확인했다(2026-11-02). 메뉴와 키보드가 필요한 항목은 `osascript`에 손쉬운 사용 권한이 없어 확인하지 못했다. `pnpm tauri dev`에서 수동으로 확인하고 결과를 이 절에 기록한다.

- [ ] Cmd+N이 앞 창에서 오른쪽 아래로 비켜난 새 창을 연다. 빈 창에서 눌러도 새 창이 생긴다. (새 창 위치 오프셋은 Finder 열기 경로로 확인함: 904,257 다음 928,281)
- [ ] 시작 직후 빈 창에서 Cmd+O로 열면 그 창에서 열린다.
- [ ] 수정한 창에서 Cmd+O로 열면 새 창에서 열리고 원래 창은 그대로다.
- [x] 이미 연 파일을 다시 열면 그 창이 앞으로 온다. (`open -a`로 a.md 재열기: 창 수 그대로, a.md 창이 맨 앞)
- [x] 앱이 꺼진 상태에서 Finder에서 파일 두 개를 선택해 열면 창 두 개가 각각 열리고 빈 창이 남지 않는다. (`open -a App a.md b.md`: 창 2개, 최근 목록에 b.md, a.md)
- [x] 앱이 실행 중일 때 Finder에서 파일을 열면 빈 창이 있으면 거기서, 없으면 새 창에서 열린다. (a.md 창 하나에서 `open -a App b.md c.md`: 창 3개, 빈 창 재사용은 미확인)
- [ ] 창 두 개를 모두 수정한 뒤 Cmd+S를 누르면 앞 창만 저장된다(제목의 `•`가 한 창에서만 사라진다).
- [ ] Cmd+F가 앞 창에서만 찾기 바를 연다.
- [ ] 마지막 창을 닫아도 메뉴 바가 남고, Dock 아이콘 클릭, Cmd+N, Cmd+O가 창을 연다.
- [ ] 수정한 창이 있을 때 Cmd+Q를 누르고 취소하면 앱이 남고, 그 뒤 마지막 창을 닫아도 앱이 남는다.
- [ ] 모든 창이 깨끗할 때 Cmd+Q는 바로 종료된다.
- [ ] Window 메뉴 아래에 열린 창 목록이 보이고 제목이 파일명이다.
- [ ] 창을 모두 최소화한 뒤 Dock 아이콘을 누르면 빈 창이 생기지 않고 창 하나가 복원된다.
- [ ] 최소화한 창의 파일을 Open Recent로 다시 열면 그 창이 복원돼 앞으로 온다.
- [ ] 빈 창에서 사라진 파일을 Open Recent로 골라 오류를 본 뒤 Cmd+O로 다른 파일을 열면 그 빈 창에서 열린다.
