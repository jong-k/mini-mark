# 클립보드 스펙

복사와 붙여넣기에서 mini-mark가 클립보드 형식을 어떻게 쓰고 읽는지 정한다. 구현은 `src/markdown-editor.ts`의 `markdownClipboard` 플러그인에 있고, 자동 테스트는 `src/markdown-editor.test.ts`에 있다.

- 작성일: 2026-10-20
- 상태: 구현 완료, 실제 앱 수동 검증 완료(2026-10-20)

## 배경

클립보드에는 한 번 복사할 때 여러 형식이 함께 들어간다. 붙여넣는 앱은 그중 하나를 골라 읽는다.

| 출처              | 클립보드에 넣는 형식                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| Notion            | `text/html`(서식), `text/plain`(마크다운 원문)                                      |
| VS Code           | `text/plain`(원문), `text/html`(색을 입힌 코드), `vscode-editor-data`(VS Code 전용) |
| 변경 전 mini-mark | `text/html`(서식), `text/plain`(서식 없는 글자)                                     |

다른 앱 사이에서 복사하고 붙여넣어 다음 결과를 확인했다.

- Notion에서 VS Code로 붙여넣으면 마크다운 원문이 붙는다. VS Code가 `text/plain`만 읽기 때문이다.
- VS Code에서 Notion으로 붙여넣으면 마크다운 코드 블록 안에 원문이 들어간다. Notion이 VS Code에서 온 내용을 코드로 판단하기 때문이다.

mini-mark는 Notion에서 VS Code로 가는 흐름을 목표로 한다. 텍스트만 받는 곳에는 마크다운 원문을 주고, 서식을 받는 곳에는 서식을 준다.

## 복사

mini-mark에서 복사하면 클립보드에 두 형식을 넣는다.

- `text/html`: ProseMirror 기본 직렬화 결과다. Slack, Notion처럼 서식을 받는 앱과 mini-mark 자신이 읽는다.
- `text/plain`: 선택 영역의 마크다운이다. VS Code, 터미널, 메모장처럼 텍스트만 받는 앱이 읽는다.

`text/plain`의 내용은 선택 범위에 따라 다르다.

| 선택 범위                                       | `text/plain` 내용                                                                    | 예                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ | --------------------------- |
| 여러 블록                                       | 블록 구조를 포함한 마크다운                                                          | `# 제목`, `- 항목 **굵게**` |
| 한 블록 안                                      | 인라인 서식만 있는 마크다운. 제목의 `#`나 목록의 `-` 같은 블록 표시는 붙이지 않는다. | 제목 일부를 선택하면 `제목` |
| 코드 블록 안                                    | 원문 그대로. 펜스를 붙이지 않고 이스케이프하지 않는다.                               | `const *a* = 1`             |
| 마크다운으로 만들 수 없는 범위(표의 셀 선택 등) | ProseMirror 기본 텍스트 추출. 블록 사이를 빈 줄로 구분한다.                          |                             |

- 마크다운은 Milkdown 직렬화기(remark-stringify)가 만든다. 목록 기호는 저장할 때와 같은 `-`다.
- 끝의 개행은 지운다.
- 드래그 앤 드롭도 같은 직렬화를 거친다.

## 붙여넣기

붙여넣기는 아래 순서로 판단한다. 처음 맞는 규칙을 적용한다.

1. 클립보드에 이미지 파일이 있으면 upload 플러그인이 처리한다. 이미지를 `assets/`에 저장하고 이미지 노드를 넣는다.
2. 커서가 코드 블록 안에 있으면 ProseMirror 기본 처리를 따른다. 텍스트를 그대로 넣는다.
3. `text/plain`이 비어 있으면 ProseMirror 기본 처리를 따른다.
4. `text/html`이 있고 코드 편집기에서 온 것이 아니면 ProseMirror 기본 처리를 따른다. HTML을 서식으로 파싱한다.
5. 나머지 경우에는 `text/plain`을 마크다운으로 파싱해 넣는다.

출처별 결과는 다음과 같다.

| 출처                               | 적용 규칙 | 결과                                                   |
| ---------------------------------- | --------- | ------------------------------------------------------ |
| mini-mark                          | 4         | 복사한 서식을 그대로 붙인다.                           |
| VS Code                            | 5         | 마크다운을 서식으로 보여 준다. `# 제목`은 제목이 된다. |
| 메모장, 터미널 등 텍스트만 넣는 앱 | 5         | 마크다운을 서식으로 보여 준다.                         |
| 웹 페이지, Notion                  | 4         | HTML의 서식을 붙인다.                                  |

- 마크다운 한 줄을 문단 중간에 붙이면 현재 문단에 이어 붙는다. 예를 들어 `ab` 사이에 `**x**`를 붙이면 `a**x**b`가 된다.
- 코드 편집기 판별 기준은 두 가지다. 클립보드 형식에 `vscode-editor-data`가 있거나, `text/html`에 `white-space: pre` 스타일이 있으면 코드 편집기에서 온 것으로 본다.

## 결정과 이유

### `text/html`을 유지한다

- 서식을 받는 앱(Slack, Notion)에 붙이면 서식이 유지된다. Notion끼리 복사할 때와 같은 결과다.
- mini-mark 안에서 복사해 붙일 때 ProseMirror가 HTML에 넣은 구조 정보를 써서 원래 노드를 정확히 복원한다.

### VS Code에서 붙여넣은 내용은 코드 블록이 아니라 서식으로 보여 준다

Notion은 VS Code에서 온 내용을 코드 블록으로 만든다. mini-mark는 마크다운 에디터이므로 마크다운 원문을 받으면 서식으로 보여 주는 편이 맞다.

### 서식 HTML이 있으면 `text/plain`을 파싱하지 않는다

웹 페이지의 `text/plain`에는 마크다운 기호가 없다. 이 경우 `text/plain`을 파싱하면 제목과 목록 같은 서식이 사라진다. HTML을 파싱해야 서식이 남는다.

### Milkdown clipboard 플러그인 대신 직접 구현한다

`@milkdown/kit/plugin/clipboard`도 복사할 때 `text/plain`에 마크다운을 넣는다. 다음 두 동작 때문에 쓰지 않는다.

- VS Code에서 붙여넣으면 코드 블록을 만든다. 위의 결정과 반대다.
- 문단 하나 안에서 선택하면 굵게와 링크 같은 인라인 서식을 버린다. 서식 없는 텍스트인지 판정할 때 서식 표시를 보지 않기 때문이다.

### 검토했으나 채택하지 않은 대안

| 대안                                | 채택하지 않은 이유                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 복사할 때 `text/html`을 넣지 않는다 | 서식을 받는 앱에 마크다운 기호가 그대로 붙는다. mini-mark 안의 붙여넣기도 마크다운 파싱에 의존하게 된다. |
| 복사 결과를 Prettier로 정리한다     | 복사 처리는 동기 함수라서 지연 로드하는 Prettier를 쓸 수 없다.                                           |

## 알려진 한계

- 일반 텍스트 안의 `*`나 `_` 같은 마크다운 기호는 `\*`처럼 이스케이프된다. 마크다운으로는 정확한 출력이다.
- 이미지와 로컬 링크 경로는 현재 문서 기준 상대 경로로 복사된다. 다른 폴더의 문서에 붙이면 경로가 맞지 않는다.
- front matter는 에디터 문서 밖에 보관하므로 전체를 선택해도 복사되지 않는다.
- 코드 편집기 판별은 경험칙이다. JetBrains IDE 같은 다른 편집기에서 붙이면 HTML 서식으로 처리될 수 있다. 문제가 생기면 판별 기준에 추가한다.
