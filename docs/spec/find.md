# 찾기 스펙

Cmd+F로 현재 문서 안에서 텍스트를 찾는 기능을 정한다. 구현은 `src/markdown-editor.ts`의 find 플러그인과 `src/find-bar.tsx`, `src/lib/find-matches.ts`에 두고, 자동 테스트는 각 파일 옆의 `.test` 파일에 둔다.

- 작성일: 2026-10-21
- 상태: 구현 완료, 실제 앱 수동 검증 전
- 범위: 찾기만. 바꾸기는 나중에 붙인다.

## 배경

Typora 1.14.10과 Anytype 0.57.4의 찾기를 관찰했다. 화면은 Anytype를 따르고, 동작은 두 앱에서 좋은 쪽을 고른다.

| 항목         | Typora                                           | Anytype                                                                      | mini-mark                          |
| ------------ | ------------------------------------------------ | ---------------------------------------------------------------------------- | ---------------------------------- |
| 위치         | 창 상단 한 줄 바                                 | 헤더 위에 뜨는 알약형 바. 본문을 밀어내지 않는다                             | Anytype                            |
| 구성         | 드롭다운, 입력란, 토글 3개, 화살표, 개수, 닫기   | 돋보기, 입력란, 개수, 지우기, 화살표 2개                                     | Anytype                            |
| 옵션         | 대/소문자 구분, 단어 단위, 정규식                | 없음                                                                         | 없음                               |
| 검색 시점    | 입력 즉시(50ms), IME 조합 중 제외                | 키를 뗀 뒤 500ms, Enter는 즉시                                               | 입력 즉시(100ms), IME 조합 중 제외 |
| 일치 표시    | 모든 일치 연한 배경, 현재 일치 검정 배경 흰 글자 | 모든 일치 강조색 글자, 현재 일치 선택 배경                                   | Anytype                            |
| 개수         | "1 / 2", 없으면 "결과 없음"                      | "1 of 97", 없으면 숨김                                                       | "1 / 97", 없으면 "결과 없음"       |
| 이동         | Enter 다음, Shift+Enter 이전                     | Enter와 아래 화살표 다음, 위 화살표 이전, 순환                               | 둘 다                              |
| 이동 시 선택 | 현재 일치를 본문 선택으로 만든다                 | 표시만 바꾸고 선택은 그대로                                                  | Anytype                            |
| 열 때 검색어 | 본문 선택 텍스트, 없으면 이전 검색어             | 본문 선택 텍스트, 없으면 이전 검색어                                         | 같다                               |
| 닫을 때      | Esc. 현재 일치를 선택하고 본문 포커스            | 지우기 버튼(Esc는 메뉴 공통 동작으로 추정). 현재 일치를 선택하고 본문 포커스 | 같다                               |
| 바 밖 클릭   | 일치 항목을 클릭하면 닫힌다                      | 닫히지 않고 본문 편집 가능                                                   | Anytype                            |

## 화면

- 찾기 바는 에디터 위에 떠 있다. 창 상단 중앙에 두고 본문을 밀어내지 않는다. 폭은 본문(`.ProseMirror`)의 최대 폭과 같고, 창이 좁으면 좌우 16px 여백을 남긴다.
- 왼쪽 알약형 영역(높이 32px, 모서리 16px)에 돋보기 아이콘, 입력란, 개수, 지우기 버튼(원 안의 X)을 가로로 둔다. 오른쪽 작은 알약형 영역에 위, 아래 화살표 버튼을 둔다.
- 색은 `src/app.css`의 기존 변수만 쓴다. 영역 배경 `--code-bg`, 테두리 `--border`, 개수 글자 `--accent`, 아이콘과 자리 표시 글자 `--muted`. 다크 모드는 변수가 바뀌므로 따로 두지 않는다.
- 입력란 자리 표시 문구는 "찾기"다. 개수는 "현재 / 전체"(예: `3 / 12`)이고, 일치가 없으면 `--muted` 색으로 "결과 없음"을 보인다. 검색어가 비어 있으면 개수 자리를 비운다.
- 본문의 모든 일치는 글자색을 `--accent`로 바꾼다. 현재 일치는 배경 `--accent`, 글자색 `--bg`, 모서리 2px다.

## 동작

### 열기

- Edit 메뉴의 "Find..." 항목(Cmd+F)이 연다.
- 본문에 선택 텍스트가 있고 줄바꿈이 없으면 그 텍스트를 입력란에 채운다. 없으면 이전 검색어를 유지한다. 검색어는 앱이 실행되는 동안 유지되고 디스크에 저장하지 않는다.
- 열리면 입력란에 포커스를 주고 내용을 전체 선택한다. 입력란이 비어 있지 않으면 바로 검색한다.
- 이미 열려 있으면 입력란 포커스와 전체 선택만 다시 한다.

### 검색

- 대소문자를 무시한 리터럴 비교다. 정규식과 단어 단위 옵션은 없다.
- 입력란이 바뀌면 100ms 뒤에 검색한다. 한글을 조합하는 동안에는 검색하지 않고 조합이 끝난 뒤 검색한다.
- Enter는 대기 중인 검색(100ms 디바운스)을 즉시 실행한다. 검색어가 마지막 검색과 다르면 검색만 하고 이동하지 않는다. 같으면 다음으로 이동한다. 한글 조합을 확정하는 Enter는 검색어가 바뀐 뒤에 오므로 이동으로 치지 않는다.
- 검색 범위는 본문의 텍스트 블록(문단, 제목, 목록 항목, 인용, 코드 블록, 표 셀) 안의 글자다. 블록 경계를 넘는 일치는 없다. 이미지 alt, 링크 주소, front matter는 찾지 않는다.
- 검색어가 비면 표시를 모두 지우고 개수를 비운다.
- 검색 직후 현재 일치는 본문 커서(선택 시작) 위치 이후의 첫 일치다. 없으면 첫 번째 일치다.

### 이동

- 다음: Enter, 아래 화살표 키, 아래 화살표 버튼, Edit 메뉴 "Find Next"(Cmd+G).
- 이전: Shift+Enter, 위 화살표 키, 위 화살표 버튼, Edit 메뉴 "Find Previous"(Cmd+Shift+G).
- 마지막에서 다음으로 가면 첫 번째로, 첫 번째에서 이전으로 가면 마지막으로 간다.
- 검색과 이동 직후에만 현재 일치가 화면 세로 중앙에 오도록 스크롤한다. 편집으로 다시 찾을 때는 스크롤하지 않는다.
- 이동은 표시와 개수만 바꾼다. 본문 선택과 커서는 바뀌지 않는다.
- 바가 닫힌 상태에서 Cmd+G나 Cmd+Shift+G를 누르면 이전 검색어로 바를 열고 검색한 뒤 이동한다. 이전 검색어가 없으면 열기만 한다.

### 편집 중 갱신

- 바가 열린 채로 본문을 클릭하고 편집할 수 있다. 바 밖을 클릭해도 닫히지 않는다.
- 본문이 바뀌면 같은 검색어로 다시 찾아 표시와 개수를 갱신한다. 현재 일치는 편집 전 현재 일치의 위치 이후 첫 일치로 옮기고, 없으면 첫 번째다. 이때 스크롤하지 않는다. 타자마다 화면이 튀지 않게 하기 위해서다.
- 문서를 열거나 새로 만들어 본문이 통째로 바뀌어도 같은 규칙으로 갱신한다. 바는 닫지 않는다.

### 닫기

- 입력란에서 Esc를 누르거나 지우기 버튼을 누르면 닫힌다. 지우기 버튼은 입력란도 비운다.
- 본문에 포커스가 있을 때도 바가 열려 있으면 Esc로 닫힌다. 본문을 클릭해 편집하던 사람이 키보드로 빠져나올 길이다.
- 닫으면 표시를 모두 지운다. 현재 일치가 있으면 그 범위를 본문 선택으로 만들고 본문에 포커스를 준다. 없으면 열기 전 커서 위치 그대로 본문에 포커스를 준다.
- 검색어는 닫아도 남아 다음에 열 때 채워진다. 닫힌 동안에는 아무것도 찾지 않는다.

### 문서 상태

- 찾기는 문서를 바꾸지 않는다. `isDirty`, undo 기록, 창 제목에 영향이 없다.

## 결정과 이유

### 화면은 Anytype를 따른다

사용자가 Anytype의 모양을 선호했다. 옵션 토글이 없어 바가 한 줄로 끝나고, 본문을 밀어내지 않아 편집 중에도 거슬리지 않는다.

### 이동할 때 본문 선택을 바꾸지 않는다

선택을 바꾸면 IME 조합이 끊기고 undo 기록과 커서가 흔들린다. 표시만 바꾸면 문서와 선택이 그대로라 안전하다. 닫을 때 한 번만 선택한다.

### 검토했으나 채택하지 않은 대안

| 대안                     | 채택하지 않은 이유                                               |
| ------------------------ | ---------------------------------------------------------------- |
| Typora처럼 옵션 토글 3개 | 사용자가 Anytype의 단순한 바를 선호했다. 필요해지면 그때 더한다. |
| 바 밖을 클릭하면 닫기    | 바를 열어 둔 채 본문을 고치는 흐름이 더 유용하다.                |

## 알려진 한계

- front matter는 에디터 밖에 보관하므로 찾지 않는다.
- 이미지 alt와 링크 주소는 찾지 않는다.
- 블록 경계를 넘는 문자열은 찾지 못한다.
- 편집할 때마다 문서 전체를 다시 찾는다. 아주 긴 문서에서는 입력이 느려질 수 있다.

## 확인 필요

다음 항목은 `pnpm tauri dev`에서 수동으로 확인한다. 확인한 결과를 이 절에 기록한다.

- [ ] 입력란에 포커스가 있을 때도 Cmd+F, Cmd+G, Cmd+Shift+G가 동작한다.
- [ ] 한글을 조합하는 동안 검색하지 않고 조합이 끝나면 검색한다.
- [ ] 본문 텍스트를 선택하고 Cmd+F를 누르면 입력란에 채워진다.
- [ ] 닫으면 현재 일치가 선택된다.
- [ ] 다크 모드에서 바와 일치 표시 색이 읽힌다.
- [ ] 바가 열린 채 문서를 열면 개수가 새 문서 기준으로 바뀐다.
- [ ] 코드 블록 안의 일치도 강조색으로 보이고 현재 일치는 배경색 위에 글자가 읽힌다.
- [ ] 바가 열린 채 본문에서 한글을 조합해도 조합이 끊기지 않는다.
- [ ] 입력란에서 한글을 조합한 뒤 Enter로 확정하면 검색만 되고 이동하지 않는다.
